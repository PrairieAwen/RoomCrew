# ADR-0002：先交付 Windows 独立会话版

状态：已接受，依据用户本轮明确开发及验收要求。它覆盖此前架构 HTML 中“所有模型连接必须先有安全 VM”的首版实施顺序，长期安全目标保留。

源码结构已按 [ADR-0003](0003-backend-layers.md) 重构；本文的会话和模型配置入口不变。Skills 后端来源校验与渐进加载已独立接入，用户技能管理界面仍未提供；MCP 和安全 VM 仍关闭。

## 验收目标

用户从 Windows 独立应用 `RoomCrew.exe` 打开窗口，手动填写模型配置，保存、测试连接、提交自然语言任务，查看同一会话内完整的公开执行轨迹及实际文件。无需用户安装 Python、启动后端或打开外部浏览器。

用户计划用“让 Agent 写一份日记”做真实模型验收。生产代码没有日记模板、日记专用分支或预置答案。模型自行决定规划、工具与委派；缺少真实经历时应询问或明确示例，不编造已发生的个人事实。是否生成了文件以实际产物为准。

## V1 技术决定

| 层次 | 实现与职责 |
| --- | --- |
| 桌面窗口 | pywebview 6.2.1，Windows WebView2；主线程运行窗口 |
| 前端 | frontend/src 的 HTML/CSS/JavaScript，无构建链、无第三方 CDN |
| 本机通信 | pywebview 具名 Python 桥；不开放 HTTP 业务 API，框架只为界面静态资源启动回环服务 |
| 后端 | 专用 asyncio 线程，用户提交立即受理；首版全局同时执行一个会话 |
| Loop | Deep Agents 0.7.32 的 create_deep_agent，不自写模型—工具生产循环 |
| 子 Agent | Deep Agents 内置 task / general-purpose；独立子任务上下文，共享当前会话产物目录 |
| 模型 | 首版支持 OpenAI 兼容 Chat Completions + 标准 function tool calling；不声称已支持所有厂商协议 |
| 持久化 | sessions.sqlite 保存产品会话/Run/轨迹；runtime.sqlite 交给 AsyncSqliteSaver 保存 checkpoint |
| 分发 | PyInstaller 目录发行，RoomCrew.exe + _internal；压缩整个目录，不单独分发 exe |

## 模型配置与不可感知边界

1. 用户配置入口接收配置名称、Base URL、模型 ID、API Key、可选 HTTP(S) 代理、单请求超时、上下文窗口。网络直连为默认行为，代理需要用户显式填写，不继承环境代理。
2. Windows DPAPI 加密完整配置，保存到 `%LOCALAPPDATA%/RoomCrew/private/model-config.dpapi`。没有明文配置临时文件；Agent 会话文件位于另一个 `data/sessions/<id>/files/` 目录。
3. ModelFactory 明确加载文件并构造 SDK，再返回 PrivateChatModel。真实客户端与凭据为代理私有属性；框架只看到通用名称和必要能力。
4. 不提供 Agent 读取/修改配置的工具，不注入 .env，不使用全局 Key 兜底，不在轨迹、checkpoint、错误中保存原始模型配置。公共配置回读永不返回已存 Key。
5. 真实模型 ID 必然出现在发往服务商的协议 envelope 中，但不注入模型消息。无法承诺模型不知道自己的身份；本产品承诺不向它提供本地真实配置和凭据。
6. 这是应用访问边界及静态加密，不是 OS 沙箱。同 Windows 用户下的任意非受限代码仍可能读取/解密该文件，因此 V1 不开放任意代码工具；第二版再实现真正隔离。
7. 远程端点要求 HTTPS；更换端点不得自动沿用旧 Key。修改配置创建新引用，原有会话可查看，继续任务需新建会话。

## 命令、执行与轨迹顺序

```text
用户表单/输入 → DesktopAPI → RuntimeThread → Runtime
  模型配置 → ConfigStore → DPAPI 文件
  提交任务 → SQLite: 用户消息 + Run → create_deep_agent
  主/子 Agent → PrivateChatModel → 真实模型接口
  模型工具请求 → Deep Agents 工具 → 当前会话真实文件
  官方公开事件 → 投影/脱敏 → SQLite 持久事件
  界面按 seq 轮询 → 连续展示主 Agent、子 Agent、工具输入/输出、终态
```

会话 ID 对应一个框架 thread，每一轮用户提交创建独立 Run。不同会话不共用历史；同一会话成功后可继续，checkpoint 自动提供历史。首版只执行一个会话，降低并发和停止语义的复杂度。请求 ID 幂等，重复发送相同请求不会再次执行。

公开轨迹包含用户输入、公开回复、模型调用起止及用量、工具名称与完整输入输出、真实子任务作用域、运行终态。它不包含隐藏思维链。首版模型正文完整响应后显示，非逐 Token 流式输出；工具过程与阶段状态实时增量显示。消息不根据界面动画生成，断开观察不会取消任务。

## 当前可用与不可用

已接入：Deep Agents 内置计划、文件读写/编辑/目录/检索、task 子 Agent、自定义真实本机时间工具。文件工具使用 FilesystemBackend 的虚拟路径检查，仅挂载会话文件目录。该目录不是 OS 级隔离。

厂商私有思考续接、签名字段和原生非 OpenAI 协议尚未逐个适配，真实验收应先选支持标准 Chat Completions 工具调用的模型；不要把“OpenAI 兼容”理解为所有厂商特性均已验证。

未接入：任意 Shell/Python、MCP、浏览器、Computer Use、安全 VM、用户技能管理、员工配置界面、房间及动作渲染。当前不添加空模块伪装支持。

文件产物清单由后端枚举真实文件得出，不采信模型自己报告。文本预览限 UTF-8 / 1 MB，不执行 HTML。模型回复与工具内容一律以文本插入界面，避免任务内容成为脚本。

## 故障与退出

- 单次请求超时由用户配置（10～600 秒），SDK 自动重试关闭；本轮总执行限 10 分钟、图递归限 80。每 Run 共享 32 次模型调用预占额度，覆盖主 Agent、子 Agent 和摘要，超额在进入 SDK 前拒绝。
- SDK 错误转换为认证、限流、超时、连接、请求不兼容或服务异常等稳定错误；不把含请求头/响应原文的异常展示出来。
- 停止按钮取消本地协程并等待确认；已经完成的文件操作保留，不能承诺撤回服务商已接收的请求或费用。
- 同数据根单实例。关闭窗口停止后端及数据库连接；意外退出后将旧 running 标记 interrupted，不自动重做工具。
- 失败、取消、意外中断会话只保留观察，首版要求新建会话继续，避免未经对账重放副作用。
- 程序升级与用户数据分开；数据和私有配置不进入发行目录。正式数据库迁移、安装器、签名及自动更新仍待后续发布阶段设计。

## 验证策略

自动回归调用真实 SDK、Deep Agents Loop、文件工具、SQLite 和 Windows DPAPI，仅把远程模型替换成测试目录内的本机协议服务。模拟响应只存在于 backend/tests，不进入发行程序；这类测试验证连接协议和调度机制，不能代替真实厂商的智能效果验收。

重点覆盖文件写入/读回、多轮历史、子 Agent 轨迹归并、配置加密和路径边界、认证错误脱敏、取消、请求幂等、重启历史与工具连接探测。静态检查使用 Ruff、mypy 和 JavaScript 语法检查。另检查原生窗口和冻结程序包。

真实模型验收由用户在应用内手动填写 Key 后进行：测试连接 → 新建会话 → 输入任务 → 核对公开轨迹 → 打开真实产物 → 继续一轮 → 关闭重开检查历史。连接探测会发起一次真实模型请求并验证标准工具调用，可能产生服务商费用；探测成功仍不代表已验证所有工具行为。

## 后续迭代

先根据真实模型验收修正兼容性和交互，再迭代凭据服务与代码/浏览器隔离、权限审批、MCP、Skills、并发调度，最后接入工作室渲染。后续安全能力按独立验收门槛开放，不把 V1 的虚拟路径包装成安全 VM。
