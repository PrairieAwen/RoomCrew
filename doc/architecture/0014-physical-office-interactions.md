# ADR-0014：符合办公逻辑的场景与动作

状态：2026-10-27；本次只修改桌面场景、素材与播放，不改变 Agent Loop、轨迹、工具授权或任务状态。

本页保留上一轮实现与验证记录。后续复查发现它未覆盖沙发/会议席配置、格边行走及真实桌前接触，原“已校准”的结论不充分；修正方案与当前规则见 [ADR-0015](0015-office-contact-correction.md)。

## 1. 从实际操作面决定朝向

此前工作动作只有正面，座位也没有方向，默认统一朝镜头；椅子始终按一个方向绘制，因此工作、休闲和起坐互相冲突。

桌面场景锚点现在包含 direction 与 purpose。普通工位面向其显示器的西北方向，安全服务台面向东北，沙发向外，会议座位分别朝桌面中心。电脑游戏也面向电脑；手机、汇报和人工提问可转向用户。旧未读结果在新任务执行时不能迫使人物背对当前操作面。朝向由结构化活动及家具几何决定，不调用模型猜动作。

office-behavior.js 负责有限朝向、短转身与内置补帧。人物转向时先暂停手部动作，约每 0.12 秒转过一个相邻方向；走路和起坐仍由原运动层负责。未读泡泡的稳定挂点与回执不改，显示不能决定真实业务成功。

## 2. 起坐与素材一致性

移动分为站起、行走、到座位后转身、落座、稳定坐姿。到达接近点不会直接坐下；实际显示朝向被保留下来，休闲后离座不会先跳回工作方向。减少动态效果仍可直接恢复最终合法位置。

四套内置形象新增 24 个有效背向/侧向姿势。显示补丁按不可变素材 ID 精确匹配，原 JSON、PNG、hash、用户帧号、两页导入合同与显式动作绑定不改。源码新目录及实际生成提示词在 `desktop/ui/studio/assets/office-v1/`。自定义素材缺少方向时不凭空绘制，优先兼容背向 idle；显式绑定仍服从用户的选择。

朝向优先于表情，避免“工作背面”因为存在“正面微笑”而被换掉。动作和朝向变化使用 100ms 短混合，每人至多一份前姿势，不逐帧解码图片。混合是有限帧的视觉过渡，尚不是完整骨骼或任意角度转身。

座椅有前、侧、背三种外观；背向椅背按腰部遮挡拆层，人物头部不被盖住。桌面按手部高度重新注册，工作方向与键盘、显示器保持一致。椅子随坐着的人旋转，离座后保持原方向，不跟着走远的人旋转。

## 3. 办公室布置与迁移

默认房间仍为 24×19 格，四个员工桌排成两行两列。接待台和安全服务台沿后侧排列，会议区靠大屏，沙发/灯/咖啡集中于休闲区，14 列为连续主通道。功能区底色从家具外沿计算，不留在旧位置；没有增加不可见碰撞墙。

监管员使用专门的双屏服务台，档案室使用文件柜组，分别标明“未接入”和“规划中”。二者不因素材更新而获得 Agent、审批、归档或跨空间记忆能力。

只有完整坐标/类型匹配旧默认模板、且无额外自定义家具的布局才自动迁移；旧自动档案设施也需匹配已知位置。自定义、移动过的家具或多个档案设施保持原样，不按 revision 盲目覆盖。保留家具 ID、人物目标、所有原有座位和业务历史，增加布局代次，迁移前验证每个接近点可达。旧默认档案 ID 保留。

## 4. 验证

Python 检查工位方阵、无重叠、通道连续、全部座位可达、方向、默认迁移与自定义布局保护。Node 检查工作/游戏/手机/人工的朝向区别、渐进转向、四套内容 ID、原素材不变及自定义素材隔离；既有动作、素材、泡泡和工作空间回归继续运行。

office_scene_smoke.py 通过真实 Deep Agents、隔离 Python、正式人工中断/恢复与产物接口验证四套图集，未使用用户真实 Key。WebView2 从本测试窗口自身导出工作、HIL、沙发画面，已目检并据此校准显示器方向与桌面高度；不读取桌面其他应用。连续记录站起、行走、转向、落座及稳定阶段，最大单帧位移约 0.093 格，混合节点最多两份。四次合成模型请求确实生成 proof.txt，人工答复后继续原任务。
