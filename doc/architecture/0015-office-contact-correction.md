# ADR-0015：修正人物穿桌与工作接触点

状态：2026-10-27。仅修改桌面表现，不改变 Agent Loop、工具、轨迹或业务状态。

## 问题与原因

上一轮的测试证明了动作标签和阶段存在，却没有证明人物与家具真的接触正确。原座点仍在桌子的阻挡矩形内部，普通工位的人物对着抽屉；素材脚底又被当作地面基线，坐姿身体没有升到椅面。导航整数节点被直接当作世界坐标，因此路线沿家具边缘而不是格心经过。会议桌按占地中心落地，后排人物会被整张桌图盖住。

现有用户的助手在沙发、员工在会议席；只在新建默认工位上验证，无法覆盖这些实际配置。

## 统一地面坐标与实体边界

导航仍以整数格索引传递，`groundCell` 也保持整数。实际世界脚点统一为 `[cell.x + 0.5, cell.y + 0.5]`，节点之间只走四邻域，不斜切家具拐角。固定家具视为连续矩形；默认布局的所有座位之间，路线节点和路段中点均至少保留 0.4 格地面余量。

椅子使用独立 `navigation.seats` 列表，不混入家具主体占地。寻路只能离开起点椅或进入终点椅，不穿越其他椅子；散步候选直接排除座位。Python 的人工换座寻路与 JavaScript 的生活/协作寻路采用相同规则。旧导航快照未包含 seats 时兼容为空列表。

普通桌子的操作侧位于右边开放的膝部空位，接近格为 `[x + width, y + 1]`，座点为该格中心，朝西北显示器。其他座位也在合法格心，不再把坐姿位置塞回家具内部。家具编辑继续校验所有接近点可达；新布置需要给操作侧留通道。

## 桌椅与身体的接触注册

桌子原图不变，显示宽度从 136 校准为 96 世界单位，按膝部空位和落地线注册，不再按图片中心凑座点。安全台同步校准比例。会议桌宽度为 168，落地线从占地中心向前缘校准，后排人物的头部保留可见区域。

人物根节点始终留在地面，身体单独放在 `crew-body` 内，坐姿按 `24 × seatMix` 抬到座面。起坐时连续变化；阴影不升高，泡泡局部挂点减去同一抬升量。原始图片、素材 ID、用户帧号和持久化选择保持不变。它是当前手绘图集的注册参数，不是对任意用户美术都成立的自动物理求解。

## 非工位接单与动作约束

`CrewWorkstationDirector` 仅消费已提交事实。助手或员工有真实活动上下文、没有会议或待答问题时，可借用未占用工位。占用同时检查持久化位置和在途目标，借座使用原有导航/起坐状态机。结束后返回原位置，不改用户保存的座位、Run 或任务结果。无空位时保留原处，以思考代替打字；没有电脑时，电脑游戏降级为手机，字幕同步说明。

真实工作执行不等待人物到位。用户手动移动中的人物不会被强行抢断；到位后若仍有工作且缺少显示器，可继续借座。会议优先控制参与人物，人工问题在实际停止位置向用户转身。

工作方向确定后，旧显式素材绑定若指向相反朝向，只在本次渲染回退到兼容片段，不修改原配置。显式片段不做自动镜像，因此工作变体必须精确匹配实际方向，不能把“都是背面”当作左右兼容。人物配置入口说明此回退规则。

## 验证与边界

- Python 检查默认布局全部座点、全部座位两两路线的格心与路段余量，同时回归旧模板升级和自定义布局保护。
- Node 检查空椅绕行、起终点入座例外、沙发接单借座、会议优先、工作结束返回原位置、坐姿抬升及反向绑定回退。
- 原生 WebView 从沙发接单，真实经过 Deep Agents、隔离 Python、人工提问/恢复、产物核对和三个工位换座。采用本机合成模型，不使用用户 Key。导出工作、人工、落座、行走和沙发画面并目检；连续采样未发现脚点侵入家具，单帧最大位移约 0.059 格，混合节点最多两份。会议席另保留一个人物以检查后排遮挡。
