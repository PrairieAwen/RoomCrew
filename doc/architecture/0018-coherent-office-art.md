# ADR-0018：以实际画面校准办公室比例

状态：2026-10-27。补充 ADR-0017；用户提供的暖色手绘办公室为视觉参照，不用一张背景图替代可交互场景。

## 问题与修正

此前每类物件按独立图片高度注册，虽然方向、路径与接触方程通过，组合画面仍出现小沙发、大人物、椅背遮身、会议桌压人和远离家具的大椭圆阴影。功能正确不能据此推导视觉协调。

当前仍使用同一 scene-v1 合同，重新登记相对尺度：桌 / 监管台 94、办公椅 48、双人沙发 94、茶几 54、会议桌 114、白板 124、书架 134 世界单位。人物保持原统一头宽，站姿、待命与新增工作姿态使用同一尺度基准，不能为某个截图单独缩放人物。

电脑桌操作侧逐向挂点继续独立维护；默认东南桌的操作脚点纵向注册为源框 0.85，避免键盘离伸出的手过高。会议桌落地挂点改为 0.72，使桌腿在前方地面、坐席在桌边，不再把整张桌图提到人物头上。椅背前景只遮挡下身，主体仍在人物之后；人物身体和泡泡共用局部变换。

这些是当前原图的作者注册值，不是任意新家具的通用数字。新素材需重新登记，单个高度字段不能代替完整接触设计。

## 工作与待命分别选图

新增 `working-v2.png`：四角色各四帧，西北两帧、东北两帧，双手向前伸到桌面。工作 / 打字 / 电脑游戏等使用独立工作片段；坐姿待命、问答、汇报仍保留原八向基准。未制作的六个方向不冒充完整工作动画。

补图由内置 image_gen 制作，原图保存在项目 scene-v1 目录；`generation-v2.json` 记录完整提示词、引用与生成身份。注册脚本只测量裁切，不重画或拉伸 PNG。每个角色有独立臀部、鞋底及工作双手中心标记；当前没有手部骨骼 IK，仍需真实近景检查手是否与键盘对应。

运行时最多附加两张内部白名单显示页，用户的原两页图集合同不变。加载器先复制图片与尺寸数组，避免附加补图修改原 manifest。Node 验证必须实际走 ensure/load 等待解码，不能只测纯补图函数，以防“目录正确但运行时拒绝新页”。

## 环境与遮挡

- 取消工位、会议区的粗边分区框，保留连续暖灰米白地砖；普通阅读界面仍为白色。
- 四沙发围茶几，使用同投影的浅色织物地毯和细边。茶几放置已有小盆栽，所有家具仍为可编辑实例。
- 家具阴影从实际绘制矩形的脚线计算，用小范围软接触阴影，不能依据占地中心生成悬浮大椭圆。
- 窗外采用独立手绘树景纹理，墙面和地面使用统一柔光。窗景贴合墙面是建筑表面投影，与家具八向原画选图是不同问题。
- 脚踏显示为小实体支撑，取消圆形悬浮底座的视觉；无输入焦点时缩小会议室悬浮输入区，完整编辑及会话模式保留。

灯光、地毯、接触求解与动画只在 desktop 中维护，不改变 Agent 状态、工具执行、人工答复或轨迹协议。

## 验收方式

1. 先用合成模型服务运行真实 Deep Agents、隔离 Python 和 ask_user 恢复，避免把动画当执行证明。
2. 由测试自己创建的 WebView2 导出客户区截图，检查全景、放大工作近景、沙发休闲、换座与总览；不依赖可能截到其他程序的桌面截图。
3. 检查手与键盘、椅背与肩颈、臀部与座面、鞋底与地面、会议桌遮挡和四沙发 / 茶几比例。数值方程与测试数量只是必要检查，不代表画面自动合格。
4. 全量 Python 回归、八组 Node、加载原数组不变、比例范围、旋转持久化及连续移动失败路径检查通过后才打包。
5. 发行资源逐字节比对源码和 ZIP；再用独立测试宿主加载发行目录实际 HTML / JS / PNG 跑原生流程。独立 exe 启动另行确认；不混称为真实模型或完整艺术验收。

后续仍需扩充其他方向的工作动作及更丰富逐帧表演；当前方案不是最终商业游戏美术或通用骨骼物理系统。
