# ADR-0027：会议室招募与统一素材显示合同

## 1. 目标与边界

将员工管理纳入会议室布置，用户点人物仍是对话入口。改善旧图集运动时的体量跳变，保留全部 Agent 能力、内容 ID、原图、用户帧号、已保存的人物和两页自定义导入合同。所有变更位于桌面显示层，后端 Loop 不依赖这些资源或动画。

## 2. 人工操作路径

“布置会议室”展开三个子选项：

1. **招募 AI 员工**：打开未保存的员工草稿，先展示素材页；五张候选卡为阿晨、小禾、小岚、守望和小橘。每张卡选择后通过同一导入/校验/解码流程更新预览，保存才绑定人物。形象不决定系统角色、提示词或工具权限。
2. **员工与 Agent 配置**：打开原有团队面板，再编辑指定成员；Agent 配置和员工素材配置继续分开。新增员工可建立独立定义或引用现有定义。
3. **编辑家具布置**：沿用原有格网、朝向、碰撞与版本检查；可再次选择“完成家具布置”。招募和成员管理不会隐式开启家具编辑。

自制形象继续从“导入本地素材”选择 JSON，PNG 与它放在同目录。导入失败或未解码时不能保存旧素材冒充新选择；取消不改变正式绑定。快速连续选择以最后一次为准，保存期间锁定选项。空闲习惯与泡泡配置折叠，优先展示形象与预览。

## 3. 素材抽象

`material-contract.js` 维护显示合同版本、动作要求、覆盖统计和内置兼容校准。执行定义只提供任务事实，素材负责实现这些视觉语义：

| 场景 | 动作语义 | 素材要求 |
| --- | --- | --- |
| 待命 | idle / standing | 导入最低要求，必须提供 |
| 移动 | walk，run 可选 | 整段固定尺度、脚点和方向；不能把同一帧复制成完整步态 |
| 普通工作 / 工具 | work / type / write | 面对显示器，工作片段与家具规格匹配 |
| MCP | phone | 通话与摸鱼手机共用语义词，实际通话优先使用配套补帧 |
| 查档 | read | 路线由表现系统负责，片段只表现翻阅 |
| 派发任务 | talk / listen | 递交演出与队列沿用现有协议 |
| 人工 / 完成 | ask / report | 面向用户，泡泡仍由入口主人物转达 |
| 起坐 | sit_down / stand_up | 臀部、鞋底、座面和椅脚分别登记；不能靠统一 y 偏移补悬空 |

动作、朝向、姿态、表情分别声明；所有角色使用同一播放器、绑定编辑器与缺失回退规则。界面按实际显示清单统计方向数，并区分“缺失”“关键帧”“含多帧片段”。多帧不等于专业流畅动画，镜像不等于新增原绘。完整制作标准仍以 [素材制作规范](../assets/asset-production-standard/README.md) 为准。

当前导入器支持 `roomcrew.avatar` v1/v2/v3，最多两页、每页不超过 2048×2048、最多 512 个裁切。`frame_size`、`pivot`、`frame_rects`、`clips` 是实际导入合同；完整骨点 authoring-profile 仍是制作规范，不能直接导入冒充已实现。

家具继续使用 `scene-v1` 的定义、占地、八向视图、操作面及接触注册；它们与人物共享 24/12 投影和座高规格，不把桌椅误当成角色动作表。更换方向选择实际源视图，不用平面旋转冒充新视角。当前家具自定义布置可用，任意家具素材导入仍未开放。

## 4. 尺度与根点处理

旧实现把每帧头部 alpha 轮廓都拟合为相同头宽。侧脸、背影、发型或手势改变轮廓，导致倍率跟着帧变化；被多个动作共用的帧也可能拿到不同倍率。

现在分两步，在加载时生成独立显示元数据：

1. `assets/registration.py` 按动作、姿态、方向汇总所有表情，共用帧的组继续合并。每组只计算一次稳健头宽倍率；保留作者原始 scale、脚底和腾空。无法可靠识别的不透明图集不强行自动拟合。不会在帧循环里读取 PNG 或重新测量。
2. 对四套**内容 ID 匹配**的人类形象，`crewCalibrateStanding` 使用配套起身末帧“实际鞋底到头顶”的距离作为角色参考，统一站立与每段步态的体量。跑步保留屈膝高度，片段中间的自然起伏不拉平。其余站立手势沿用共同基准倍率。小橘保持已有固定规格；自定义内容即便名称相同也不进入这套私有适配。

配套起身的地面原点是椅脚，独立人物是 actor ground；参考计算显式使用 `standing_foot`，不把鞋底与椅轮的投影差算成腿长。坐姿配套图的接触注册不改动。泡泡与人物共同读取 `display_registration`，挂点加载时固定，保持同帧跟随。

不写回 PNG、原清单和素材目录；只在显示副本追加允许的补页。关闭“统一动作体型”仍采用作者原注册。旧图中身体比例、衣服和手脚造型的差异无法仅靠等比校准消除；本次不宣称完成骨架绑定、全部方向精修或所有接触验收。

## 5. 验证

- 五套真实 PNG 的固定组倍率、原图/清单不变、短体型保留和不透明图集回退。
- 实际显示补页的站立/行走尺度、起身末帧参考、原注册不变及自定义 ID 隔离。
- 原生招募子菜单、五张卡片、预览、加载锁、保存、重开、连续选择与取消；导出同尺度比较图目检。
- 原生真实 SDK、Python、人工问答及连续起坐/行走；保持单向表现、工作朝向和泡泡归属。

2026-11-02 验收结果：177 项 Python 测试通过，全部 Web 回归通过，Ruff 与 Mypy（118 个源文件）通过。真实 WebView 的招募、保存与取消通过；四角色连续起坐、行走、转向、落座通过，最大采样位移约 0.164 格，未检测到移动中进入设备实体占地。角色点击仍恢复对应独立聊天，不误开配置或新建空会话。

候选 exe 使用独立合成模型完成九次模型响应、一项 MCP 调用、随包 Python 和文件 CRUD，实际结果文件校验通过。真实鼠标展开会议室子菜单与招募页，五套形象和自定义导入入口可见。导出全景、工作近景、连续起坐与五角色同尺度比较图目检。候选 UI 与源码逐项哈希核对一致。测试使用独立 `.cache` 资料，不包含用户 Key，不产生真实定时任务；合成服务验收不等于外部模型厂商兼容性复测。
