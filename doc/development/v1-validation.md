## 验证的实际边界

上述模拟模型测试验证协议、Loop、工具、存储与交互连接，不证明真实服务商的模型能力或自然语言任务质量。原生集成通过 WebView 内的测试驱动操作真实页面，没有替换生产接口；测试代码不进入发行程序。Windows UI 自动化辅助工具在本机无法取得点击几何，故未把它声称为完整鼠标点击回归。

冻结程序已在当前机器启动。尚未在全新、未安装开发工具的 Windows 机器验证 WebView2 / .NET 前提、企业策略和安装体验；未完成签名、安装器、自动更新和安全 VM 验收。

## 等待用户进行的真实模型验收

1. 解压完整 Windows zip，启动 RoomCrew.exe，手动填写实际 Base URL、模型 ID、Key、请求超时和模型上下文窗口。
2. 保存并测试连接。该测试会请求模型生成一个标准工具调用，不能仅靠普通文本响应通过。
3. 新建会话，输入自己的日记任务；如要求真实内容，提供必要事实，并按需要要求保存为文件。程序没有日记模板或预设完成答案。
4. 核对公开轨迹中的实际工具请求和输出，打开右侧真实文件；不要仅以“模型说完成”为验收。
5. 在成功会话继续一轮，确认模型看到前文；关闭应用再打开，确认轨迹与文件仍在。
6. 可另建会话验证委派员工和停止；是否委派取决于模型判断，简单日记不要求强制调用子 Agent。

Key 只在用户应用内填写，不发到聊天中。若失败，提供不含 Key 的界面错误码、服务协议、模型 ID 和操作步骤，再修正兼容性。
