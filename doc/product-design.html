PRODUCT / 01

文档基线、约束与决策状态

本项目暂称“数字工作室”。用户在一间可以自行布置的工作室中扮演老板，招募和配置数字员工；通过助手组织真实任务，通过监管员管理敏感能力。情绪价值来自空间归属、人物表现和真实协作反馈。

阅读时先区分三个层次
  • 现有 demo：已经演示布局、静态角色、表单、轨迹和授权状态；不等于真实 Agent、SQLite 持久化或 VM 已接通。
  • 本文的产品基线：结合已确认需求形成的可实现规则；标注“建议”的数值与默认项可在评审中调整。
  • 技术可行性门槛：虚拟化安装、登录态隔离、动画制作和任务恢复需先做 PoC；不能用界面演示替代这些验证。
项目当前基线状态
首发平台可分发的 Windows 桌面应用；建议先验证 Windows 11 x64。macOS 仅保留适配接口。Windows 已确认版本矩阵待验证
目标定位面向喜欢装扮、角色和 AI 尝鲜的个人用户；通用工作台，不以完整复刻 Codex 为目标。已确认
表现形式固定视角、手绘 2.5D，可平移缩放的固定边界画布；物件独立摆放。已确认
最小团队老板、助手、监管员三个系统角色常驻；其他员工由用户添加。已确认
本地数据SQLite + 本地文件夹；凭据进入独立的安全域，普通数据库只存引用。已确认
界面状态当前美术方向已确定，具体布局与细节仍可迭代。设计中
本文数值帧数、性能、并发、资源大小为工程起点；需要实测后调整。目标，非实测

PRODUCT / 02

六个技术问题怎样体现在产品中

本节将本轮六个追问转换成用户可见行为；技术实现与旧版覆盖核对见技术文档核对表。不能只展示“数字人在忙”，还要能看清实际工作、阻塞、权限和结果。

问题产品行为技术方案
Q1 协作到人物委派 / 接待 / 工作 / 汇报由真实任务事件驱动。普通问答可原地提示，不每次强制走动；动画失败不丢需求。消息—事件—表现
Q2 写代码、工具与 MCP成员可临时写代码解决逻辑任务，显示运行、错误修复和真实成果。MCP 的服务 / 工具 / 范围 / 版本可查。工具与执行闭环
Q3 Computer Use 与登录账号任务在受控浏览器操作，人工登录期间 Agent 停止观察和输入。通用桌面操作在无长期凭据的任务环境。电脑与账号模式
Q4 大模型超时排队、等待首输出、生成中、重试与失败分别显示；可取消，已完成成果保留。工具长任务单独显示。时限 / 重试 / 恢复
Q5 上下文压缩较早历史可整理为摘要，来源仍可查；当前约束、用户纠正和未决效果保留。超限时明确拆分任务。上下文管理
Q6 多 Agent 通信事项里能看谁分派、谁接收、谁在复核、等待谁；已送达与已完成分开。角色轨迹仍只在点击后查看。协作协议

关键产品边界

  • 在 VM 内由本人登录是默认路径。宿主已经登录不等于本产品可以把所有网站状态一键搬入；仅对已验证的服务连接 / 导出提供迁入。
  • 带账号的受限浏览器与任意代码 / 桌面操作分域；不提供“无限制访问账号桌面”又保证秘密绝不可见的矛盾承诺。
  • 模型超时不能完全消灭，产品要能解释、有限重试和恢复；不因此重复提交订单 / 发信。
  • 摘要是有损整理；完整本地记录和证据按保留政策管理，不能假装无限上下文或把历史批准当新权限。

PRODUCT / 03

产品定义与两条体验循环

一句话定义

在自己布置的数字工作室里，和一支可招募、可配置、会真实做事的数字团队一起工作。空间承载人物与工作状态；事项与成果提供实用价值；权限管理使用户知道什么正在被访问、谁在使用。

空间循环布置 → 入驻 → 互动 → 留下工作痕迹 → 再布置
工作循环交代需求 → 分派 → 执行 → 审批 / 校验 → 交付 → 验收

核心价值与设计原则

  • 归属：用户可以改名字、形象、家具、房间布局和团队配置；换装修不影响已有任务、授权与文件。
  • 陪伴：角色有稳定的表达方式和适量生活动作；不会用负面情绪逼迫用户上线。
  • 能干：任务有清晰目标、进度证据、文件与可验证结果；不能只有“看起来在忙”的表演。
  • 掌控：老板决定团队能力、模型和授权；可以中断任务、撤销能力、查看轨迹与搬出数据。
  • 如实：工作、等待、失败与权限暂停分别表现；不会将模拟事件、估算或动画当成真实完成。
  • 低打扰：多数时候房间就是房间；点击角色或出现必须处理的请求时，再打开详情。

情绪表达的边界

角色可以庆祝完成、礼貌求助、坐下休息，也可以表达“这一步没做成”。不引入必须喂养才能执行任务、家具等级限制工作能力、持续制造焦虑、角色以忠诚度惩罚用户等机制。初版不做强制养成和抽卡；这些不是工作台闭环的前置条件。

PRODUCT / 04

用户假设、使用场景与非目标

以下是待访谈验证的用户假设，不是已经完成的市场结论。首轮验证应分别观察“愿不愿意布置”与“任务是否真正有用”，避免仅凭截图喜欢就判断留存。

用户来这里做什么重要体验需要验证
空间装扮与模拟经营爱好者拥有一间小工作室，设计老板形象、员工和家具。可玩、可收藏、可表达自己，布置后有反馈。没有真实工作需求时是否仍有合理使用频率；装扮是否影响效率。
个人创作者 / 学生 / 自由职业者整理资料、做文档、写简单代码、处理网页信息。把需求交给熟悉的伙伴，得到文件与可以检查的结果。可接受的任务范围、质量与模型费用。
AI 工具爱好者 / 轻度开发者配置模型、技能、工具和个人工作流。能调试、能追踪、能替换模型，不被固定角色能力限制。配置复杂度与对多语言、VM 资源开销的容忍度。
重视本地数据的个人用户在清楚的权限下处理个人资料和账号操作。数据可见、可备份；登录会话有明确授权与撤销。愿意接受的安装前置条件、审批频率和资源占用。

首发任务场景

  • 资料整理：导入一组文件 → 分类、摘要、索引 → 输出整理结果与待确认问题。
  • 文档制作：依据用户给定内容生成文档 → 预览 → 保存到用户确认的位置。
  • 代码与脚本：在隔离环境中生成、运行和检查代码 → 展示输出、错误和产物。
  • 受控浏览器：浏览公开网页；对需要登录的站点走单独授权流程。
  • 团队讨论：围绕一个任务召集会议，形成可执行的决定与任务拆分。

不作为首发交付范围

  • 完整的企业组织 / HR / 财务系统；多人在线同一房间；实时多人协同装修。
  • 完整 Windows 桌面自动化、自动接管用户日常浏览器全部标签和账号。
  • 任意高风险网站操作都能自动判断业务后果；所有外部副作用的通用撤回。
  • 移动端、完整 macOS 发行、开放公共素材商店及交易体系。
  • 无限员工、无限上下文、无限并发或“全自动做任何事”的承诺。
PRODUCT / 05

角色体系、最小团队与能力配置

角色产品职责能配置不可被外观改变的边界
老板 / 用户化身交代目标、管理个人事项、审批、验收、布置与移动自己。名字、外观、服装、姿态、默认接待方式。不是自动运行的模型角色；老板审批必须来自用户操作，不能由别的角色代点。
助手需求澄清、意图分派、跟进进度、组织会议、汇总成果；无人合适时可在授权能力内自己执行。外观、沟通风格、模型、技能和工作方式。不能因为“监管者 / 管理者”提示词而获得安全审批权。
监管员展示权限申请、托管能力引用、报告使用与拒绝结果。外观、名字、解释口吻；策略由专用配置界面管理。是否放行由独立安全后端决定；角色对话不能修改审批结果。
团队成员按用户配置的技能和模型执行任务，可参与讨论、接单和汇报。名字、岗位显示名、外观、模型、Skills、工具请求范围、工作说明。岗位名称、技能说明和动画均不能授予系统权限。

不可破坏的团队约束

  • 每个工作空间恰有一个老板、一个助手、一个监管员；这三个系统身份不允许删除、转为普通员工或停用。
  • 三者可以改名和换外观；内部身份 ID 与系统职责保持稳定。把普通员工名字改为“老板”不产生审批权。
  • 普通成员可以归档或移出；未完成事项必须选择转交、暂停或取消，不能静默丢失。
  • 删除成员配置不应自动删除其历史轨迹或已交付成果。历史记录仍显示当时的成员身份快照。
  • 首发建议界面支持 12 个可见角色的目标场景，真正执行并发另设上限；该值是测试范围，不是长远产品硬上限。

形象、能力、模型、权限四项分开

一个外观包描述如何被看见；技能包描述能调用哪些工作方式；模型配置决定如何推理；权限策略决定本次请求能否访问资源。用户可以给同一个形象更换工作能力，或给相同能力换上完全不同的形象。更换模型和技能不继承额外凭据。

PRODUCT / 06

信息架构与页面职责

区域 / 页面内容关键操作显示规则
左侧：我的工作空间当前工作空间、工作室、会议室、老板事项、外观与家具、模型、数据与存储。切换工作区、进入配置、管理事项。保持稳定，布置时不被替换成另一套导航。
中央：场景画布办公室、会议区、会客区、老板位置、角色、独立家具和局部状态。平移缩放、选择角色、布置、移动老板、交代需求。主要视觉面积；面板收起后应能扩大。
右侧：我的团队最小三角色与已加入成员，少量状态提示。点角色、添加成员、收起详情。默认仅团队列表；不自动铺满全员轨迹。
角色详情该角色的事项、轨迹、配置；监管员以授权记录为首个页签。定位任务、继续对话、查看证据、编辑配置。必须由用户点击角色或明确选择查看该角色触发。
老板事项老板自己的待办、需要审批 / 验收的事项、转派和截止信息。新增、指派、调整状态、批量整理。全空间任务概览可作为独立视图；不能混淆为老板亲自执行全部任务。
模型配置连接配置、模型能力、凭据引用、默认与成员覆盖配置。配置检查、连接验证、绑定成员、查看用量。凭据录入转入受保护流程，不出现在普通任务对话。
添加 / 编辑成员形象、岗位、模型、技能、工作方式、申请的工具范围。预览、校验、加入团队、测试一个低风险样例。保存本地；外观缺动作时明确提示能力降级。
素材与布局管理内置 / 自制家具、角色包、规范校验、布局版本。导入、放置、撤销、打包、恢复。素材错误不应导致整个工作空间无法打开。
监管与授权待审批、已托管、使用记录、期限、撤销、账号连接状态。批准、缩小范围、拒绝、撤销、重新登录。显示实际资源与动作；不把“监管员在线”当成隔离已生效。
数据与存储工作空间目录、备份、导出、保留期、VM 健康与空间占用。移动 / 备份、恢复、导出、清理可恢复内容。用用户能理解的容量和状态解释，必要时才展开技术细节。

默认阅读优先级

场景 → 当前对话 → 必须处理的请求 → 用户主动打开的详情。角色头顶只显示短状态，不长篇滚动内部对话；多个并发任务以角色详情和事项列表承载，房间不堆满通知气泡。

多空间导航与全局提醒

空间选择在左侧稳定存在，右侧团队、人物详情与轨迹绑定当前空间。全局只展示必要的后台与待处理计数，打开卡片时显示确切空间；审批窗口不因主场景切换而悄悄改变对象。

PRODUCT / 07

多个工作空间：独立工作室与后台任务

用户可以创建“个人学习”“开发项目”“资料整理”等多个工作空间，每个空间有自己的老板、助手、监管员、员工、布局、事项、资料、模型与工具配置。左侧“我的工作空间”用于选择；右侧“我的团队”始终只显示当前空间。

操作可见行为
创建 / 重命名选择本地目录与名称，初始三角色独立建立。允许同名，界面以明确路径 / 标识消歧。
切换保存相机 / 布局草稿，恢复目标空间；旧轨迹、旧人物回包和未提交操作不闪入新空间。
后台继续离开画面不自动终止已接受任务；可选继续 / 暂停，显示后台和待处理计数。
待处理请求卡片标明空间、成员、事项。打开时准确定位，不能因为当前显示另一空间就误批。

PRODUCT / 10

关键场景：老板走到沙发并坐下

默认接待规则

跟随老板当前的有效接待位置。老板坐沙发、在会议桌旁或站在别处时，员工优先去对应的“倾听 / 汇报锚点”；只有用户选择“在老板工位接待”，才固定去桌前。

完整操作与可见反馈

步骤用户 / 系统动作角色表现规则与记录
1用户点击沙发，打开“坐下 / 走过去 / 查看属性”。沙发座位出现预览点；老板当前位置保持不变。明确目标座位与朝向；没有坐姿资源时不展示可用的“坐下”。
2用户选择“坐下”。目标座位高亮；老板当前动作准备结束。检查座位容量、是否被预约、可达出口、动作兼容。
3目标座位预约成功。若原本坐着，先起身；否则准备移动。同一席位只分给一个角色；目标预约短时有效。原座位仍保持占用，直到身体起身离开。
4规划到沙发入口的路径。老板沿路行走，必要时绕过其他家具。运行中导航版本变化时重规划；失败不穿墙瞬移。
5到达入口并对齐。停步、转向到匹配座位方向。到达容差与方向合法后进入落座动作；不能省掉枢轴对齐。
6执行坐下动作。从站姿过渡到坐姿；沙发前沿正确遮挡下半身。角色与家具按素材锚点匹配；坐下时仍可打开详情和输入需求。
7进入坐姿待机。呼吸 / 轻微生活动作；支持低动态或静态模式。保存当前占用锚点；“正在坐着”是空间记录，不是任务完成证据。
8更新老板接待位置。沙发旁的倾听点成为员工前来的目标。接待策略版本更新；不把任何安全权限附着到沙发本身。
9用户输入 @某成员。该成员走到沙发旁，面向老板倾听。老板无需起身；没有合适站位时排队或在对话中接待。
10用户点地面上的“到这里”。老板起身、释放座位，再走向目标。释放发生在站起过渡安全完成后；允许保留原座占用并预约一个目标；不能同时占用两个座位。

必要的失败分支

  • 座位已被占：显示占用者，提供换座 / 稍后 / 取消；不强行赶走角色。
  • 通路堵塞：指出无法抵达的入口；保留用户的坐下意图，但不无限循环找路。
  • 素材缺失：提示“当前外观不支持此坐姿”，允许仅走到沙发旁；不把站立图压扁伪装成坐下。
  • 走到一半用户改目标：确认新意图并使旧回调失效，按阶段取消旧预约，再从合法位置重规划；落座 / 起身途中在安全边界转换。
  • 应用重启：重新检查座位、资源和布局版本；不合法则回到附近安全站位。
  • 用户只想快速交代需求：允许直接输入并先接单，视觉移动可并行或跳过。

老板的姿态与任务互不绑死

老板坐下、喝饮料、走动或离开画布，不改变他对任务的审批和验收身份。角色坐在沙发上时仍能看到事项、批准或拒绝；审批框显示谁请求什么，不要求老板先走到监管台。

坐姿的接触点与遮挡

角色的脚底点用于在地面行走与排序，骨盆点用于对齐沙发座面，两者用途不同。落座时保留正确身体比例；沙发靠背在人物后，前沿 / 扶手按姿态挡住对应部分，不能简单把整张人物图放到整张沙发图下面。老板在座面稳定后更新接待位置；助手站在可达的倾听点，与老板朝向相配。

用户追加需求

新信息保存为任务修订。执行中的步骤只在安全边界重新规划；已经发送的邮件、发布的内容或写入的远端数据不能假装回到未发生状态。发生影响授权范围的变化时，旧批准不适用于新请求。

完成与验收的证据

  • 文档：可打开的文件、生成来源范围、格式检查与预览。
  • 代码：执行记录、实际输出、适用的测试与错误；明确哪些没有运行。
  • 资料整理：输入清单、分类结果、摘要来源与未识别项目。
  • 网页操作：访问范围与操作回执；涉及提交时附用户批准的内容摘要。
  • 模型给出的“我完成了”只能作为候选摘要，不能单独触发已完成。

取消与紧急停止

普通取消允许清理当前环境并保留已完成产物；紧急停止优先切断执行与受控出口，随后报告哪些调用已经完成、哪些结果未知。撤销授权只阻止后续使用；对已发生的外部操作，显示实际可撤回能力，不能承诺通用撤销。

完成与关闭不是同一个瞬间

满足产物标准后仍需关闭该任务的安全作用域；取消也要确认执行停止与权限关闭。界面可显示“成果已保存，正在关闭权限”。如果外部操作结果未知，保留“需要核实”，不能用一次正常动画把它变成无风险的成功 / 失败。没有使用安全域的纯本地事项无需等待不存在的权限同步。

PRODUCT / 16

监管员、登录态与敏感操作授权

产品承诺的准确表述

AI 可以申请使用指定资源的受限能力；不直接拿到原始密钥或登录态文件。监管员形象对应独立安全后端，后端逐次核验请求。已经登录的浏览器仍然拥有账号能力，需要限制操作与副作用，不能仅靠隐藏 Cookie 宣称安全。

  1. 成员提出结构化操作请求，例如“用账号 A 读取 example.com 的某类页面”。
  2. 监管员先查当前有效授权；没有匹配授权时暂停该敏感步骤，并给老板显示请求。
  3. 老板看到：申请人、任务、账号、准确站点、允许动作、数据去向、期限、次数、潜在副作用。
  4. 老板批准、缩小范围、拒绝或稍后处理。用户修改范围后，展示更新后的实际请求再确认。
  5. 批准转为监管员持有的能力记录；成员取得操作结果或不可导出的引用，不取得原始凭据。
  6. 每次实际使用都重新检查成员、任务、账号、资源、动作、期限、次数、撤销状态和执行内容。
  7. 到期 / 耗尽按权威规则拒绝新使用；撤销和任务关闭先显示处理中，安全后端确认后显示生效。已派发请求单独核实；必要时重新申请。

当前任务为这一次资料整理读取限定站点。绑定任务与成员，任务终止后失效，不自动继承到新任务。
当前任务内限时本任务未来 30 分钟读取限定账号页面。时间与任务两个条件同时满足。30 分钟是建议选项，不是通用安全标准。
外部写入 / 提交发送邮件、发布内容、提交订单、删除远端数据。连接器 / 模板支持时按具体内容和目标审批；通用网页可能有自动保存，不能把打开页面当成绝对只读。
数据发送给模型将页面正文交给某云端模型总结。与使用登录态分开管理；本地保存与不会离机是两种不同设置。

老板不在桌前也能审批

审批不是空间里的小游戏。老板坐沙发、在会议室或缩小场景时都能直接处理。监管员可以走过来提示一次；待审批卡片持续存在，但不每隔几秒重复打扰。普通用户可以在事项中稍后处理；超时永远不自动批准。

账号与凭据生命周期

  • 账号由用户在受控登录环境中完成登录；相关输入期间暂停不必要的截图、轨迹正文采集与模型观察。
  • 多个账号按账号引用隔离，切换账号重新校验；同一个域名的另一个账号不能复用原授权。
  • 凭据失效时显示重新登录；不会把登录页面的失败误报为整个模型不可用。
  • 解除账号连接会撤销相关授权，并说明是否同时清理已保存会话；清理不可恢复内容需要明确确认。
  • 普通任务日志不保存 Cookie、Token、私钥、完整认证 Header 或可复用的登录态导出。

无法实现通用精确判断时的体验

网页按钮的业务含义不总能自动识别。对缺少受限 API、又拥有高权限账号的通用浏览器操作，必须降低自动化范围，展示会话级风险并要求用户处理关键提交。首发不承诺对所有任意网页都能自动完成细粒度业务授权。

授权界面必须显示中间态

状态用户文案 / 允许操作
批准提交中“正在与监管员同步”；不提前显示能力已可用。
撤销中本地停止发起，等待安全后端确认；显示在途操作清单。
已撤销显示生效时间与范围；已经发送到外站的操作可能仍需核实。
安全域离线显示状态待同步；不能把缓存有效显示成当前保证。
任务关闭中本地执行已停 / 权限关闭待确认分开显示；外部未知结果继续核实。

对任意网站，打开页面、点击或填写都有可能触发站点脚本请求。授权项区分“服务 API 的准确动作”和“某账号在某站点的受控浏览会话”。后者明确提示站点可能改变自身状态；高风险操作优先可信连接器或人工接管。用户关闭浏览器窗口、撤销会话、退出账号也有不同含义，不能用同一按钮文案混淆。

关闭成功还需要已经登记的浏览器 / 执行会话和网络出口确认停止；监管员写下“已撤销”不能替代这些确认。失联保留处理中；有不确定外部效果则继续核实。

人工登录与自动化的输入所有权

进入人工登录先确认 Agent 已停止输入与模型采集；界面持续标明“仅你可操作”。切回自动化取得新观察和控制版本，旧点击不再生效。关闭窗口、停止 Agent、退出账号和删除会话各有明确文案与实际确认，不能混为一键假成功。

收紧到离线的真实状态

切换到严格离线先停止新请求，再确认已有模型流 / 网页 / 工具连接关闭；完成前显示“正在切换”。任务文字、共享上下文或普通成员不能扩大模式与数据出口。

行为层次

  • 移动状态：静止、寻路、行走、转向、对齐、被阻挡。
  • 姿态状态：站立、坐下过渡、坐姿、起身过渡。
  • 工作表现：空闲、倾听、工作、等待输入、等待授权、汇报、失败、暂停。
  • 这三组状态组合，但由兼容矩阵约束；例如“坐姿 + 倾听”合法，“坐下过渡 + 开始行走”需要先安全切换。
  • 用户有最终控制权；生活动作可中断，长动画可以加速或跳过，减少动态模式保留静态姿态与文字。

画风与清晰度

以用户最后提供的温暖手绘办公室为风格基线：固定 2.5D、细线稿、柔和光影、可读表情和统一材质。清晰度通过足够的源图尺寸和缩放策略保证；不采用粗颗粒缩放来代替精细美术。

首发动作的真实门槛

老板、助手、监管员三个内置形象必须有四向行走与内置沙发 / 办公椅 / 会议椅所需的坐下、坐姿、起身兼容资源，才能验收核心交互。静态图片只用于 demo / 头像；用户自制包分为静态预览、可移动、可就座三个等级，在导入时明确标注。资源不足是动作不可用的原因，不伪装为已完整适配。

换目标、资源加载和窗口切换都可能产生迟到回调，系统只接受当前动作计划的阶段反馈。用户不必理解这些技术字段，体验上应体现为：角色不来回闪回、不双坐、不因多次点击播放一串过时动作。

后台、恢复与换设备的补充规则

  • 隐藏窗口不会让坐着的老板失去席位；只有目标预约会过期，稳定占用在明确释放 / 修复时改变。
  • 重启 / 恢复后先对账，再更新画面；登录授权不因载入旧备份而复活。
  • 系统睡眠或 VM 暂停可能使短期权限失效，界面说明需要重新核验，不悄悄延长有效期。
  • 多窗口看到相同人物位置；只有一个窗口负责驱动动作阶段，切换后不会重复完成或抢占。

排障无进展也有正常出口

同一异常连续两轮没有新证据时，转为需要本人决定，列出已尝试方法、结果和缺口。用户可提供新信息或有限预算；换员工、换模型也不清空失败记录。未复现 / 未验证状态如实保留。
